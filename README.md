# WestFace Mystery Gift · AR საიტი

Netlify-ზე დასაყენებელი პროექტი. მომხმარებელს არც კოდის აკრეფა სჭირდება და არც ანგარიშის შექმნა. ადმინისტრატორი პოსტერის ფოტოს ატვირთვისას თვითონ ირჩევს შედეგს: **პოსტერის ღირებულების მოგება** ან **არ მოიგო**. ფასდაკლება არ არის.

**არსებული საიტის განახლება:** ახალ ZIP-ში არსებული ფაილები ატვირთე იმავე GitHub რეპოზიტორიაში, ძველი ფაილების ჩანაცვლებით. აუცილებლად გადაიტანე ახალი `build.mjs`, `package.json`, `package-lock.json`, `netlify.toml` და განახლებული `public`, `netlify`, `tests` საქაღალდეები. Netlify-ზე გაუშვი ახალი Deploy. Publish directory ახლა `dist`, Build command კი `npm run test && npm run build` არის. არსებული გარემოს ცვლადები და ატვირთული პოსტერები იმავე Netlify პროექტში დარჩება. ძველ პოსტერებს ფასი 45 ₾ ექნებათ, ახალზე კი თავად მიუთითებ.

## 1. გაშვება Netlify-ზე

1. გახსენი ZIP და მიიღე პროექტის ფაილები (`public`, `netlify`, `package.json`, `netlify.toml` და სხვა).
2. GitHub-ზე შექმენი ახალი private repository და ატვირთე პროექტის შიგთავსი, არა დამატებითი ზედა საქაღალდე. `.env` და `node_modules` არ ატვირთო.
3. Netlify-ში აირჩიე **Add new project → Import an existing project → GitHub** და აირჩიე რეპოზიტორია. საიტი ფუნქციებს თავად ააწყობს `netlify.toml`-ის მიხედვით.
4. Netlify-ს პროექტის პარამეტრებში, **Environment variables**, დაამატე (Functions და Build scopes ან All scopes):

   | ცვლადი | მნიშვნელობა |
   |---|---|
   | `ADMIN_PASSWORD` | შენი ძლიერი, უნიკალური პაროლი (მინ. 12 სიმბოლო) |
   | `SESSION_SECRET` | ახალი შემთხვევითი საიდუმლო სტრიქონი (მინ. 32 სიმბოლო) |

   საიდუმლოს გენერირება Mac Terminal-ში შეგიძლია `openssl rand -hex 32` ბრძანებით. ეს ცვლადები არ შეინახო GitHub-ში.

5. გააკეთე ახალი Deploy. საიტი უნდა გაიხსნას `https://შენი-საიტი.netlify.app`. **მხოლოდ HTML-ის Drag & Drop გამოქვეყნება საკმარისი არ არის** — აპს Netlify Functions და Blobs სჭირდება.
6. ადმინისტრირების გვერდია `https://შენი-საიტი.netlify.app/admin`. გახსენი, შეიყვანე პაროლი.

Netlify-ს მიმდინარე პაკეტის პირობები და გამოყენების ზღვარი გადაამოწმე ანგარიშზე. საცავში მონაცემები ინახება ხელახალი Deploy-ის შემდეგაც.

## 2. პოსტერის დამატება

- ატვირთე ზუსტად ის ფოტო, რომელიც ფიზიკურ პოსტერზე დაიბეჭდება — ჩარჩოსა და ზედმეტი ფონის გარეშე.
- დაარქვი სახელი.
- მიუთითე პოსტერის რეალური ღირებულება ლარში და აირჩიე შედეგი: **მოიგო — პოსტერის ღირებულება** ან **არ მოიგო**.
- დაადასტურე, რომ პოსტერი განსხვავებულია და შედეგი საბოლოოა, შემდეგ დააჭირე **შენახვა და AR-ის განახლება**.
- დაელოდე 100%-ს; სისტემა ხელახლა შექმნის ყველა არსებული გამოსახულების ამოცნობის მონაცემებს და ავტომატურად გამოაქვეყნებს.
- ტელეფონით შედი მომხმარებლის მთავარ AR გვერდზე, მიეცი კამერის ნებართვა და მიუშვირე ფოტო ან დაბეჭდილ პოსტერს. როცა ყუთი გამოჩნდება, შეეხე ან დააჭირე საჩუქრის გახსნის ღილაკს.

ეს საწყისი ვერსია მხარს უჭერს მაქსიმუმ 40 სხვადასხვა AR პოსტერს. ატვირთვა კომპიუტერიდან სჯობს, რადგან AR დამუშავებას დრო და მეხსიერება სჭირდება. ძალიან მსგავსი ფოტოები არ გამოიყენო. მეტი პოსტერისთვის საჭიროა შემდგომი ოპტიმიზაცია (დაყოფილი AR კატალოგები, კამერის ამოცნობის სისწრაფე და საცავის მართვა). დაბალი დეტალიზაციის, ბზინვარე, მუქი ან ერთფეროვანი ფოტო შეიძლება ცუდად ამოიცნოს.

შედეგი გამოქვეყნების შემდეგ აღარ იცვლება, რათა უკვე გახსნილი საჩუქარი არ შეიცვალოს. ადმინისტრირების სიაში გამოჩნდება ყველა პოსტერი თავისი შედეგით.

არამომგებიანი პოსტერის გასწვრივ არის „წაშლა“. დაადასტურე წაშლა და დაელოდე AR ბაზის ხელახლა დამუშავებას. პოსტერი აღარ ამოიცნობა და 40-პოსტერიან ლიმიტში ადგილი გათავისუფლდება. გამარჯვებული პოსტერის წაშლა დაბლოკილია; მისი პრიზის ჩანაწერები დაცულია. წაშლამდე დარწმუნდი, რომ მომხმარებელს აღარ ესაჭიროება ამ პოსტერის დასკანირება.

## 3. მოგების მოთხოვნა

გამარჯვებულს უჩნდება ღილაკი „მოგების მოთხოვნა“. ავსებს სახელს, ნომერსა და მონაცემთა გამოყენების თანხმობას. მოთხოვნა ჩანს შენს ადმინისტრირების გვერდზე, პოსტერის ფოტოთი, ნომრით, თარიღითა და თანხით.

1. გადაამოწმე საკუთარი გაყიდვების ჩანაწერით, რომ ეს მომხმარებელი რეალური მყიდველია.
2. დაუკავშირდი ტელეფონით; თანხა ხელით გადაურიცხე.
3. მხოლოდ ამის შემდეგ დააჭირე „თანხა გადარიცხულია“ და დაადასტურე.

სისტემა თითო პოსტერზე მხოლოდ ერთი გადახდის სტატუსის დაფიქსირებას უშვებს. ეს არ ნიშნავს ბანკში გადარიცხვის ავტომატურ შეჩერებას: ხელით გადარიცხვის წინ აუცილებლად შეამოწმე სტატუსი, არ გადაარიცხო მეორედ. ერთსა და იმავე ნომერზე განმეორებითი მოთხოვნა არ დუბლირდება.

მნიშვნელოვანი: AR კამერა ფოტოს ამოიცნობს, მაგრამ ვერ დაამტკიცებს, რომ იგი ფიზიკურ პოსტერზეა დაბეჭდილი ან მყიდველს ეკუთვნის. ასევე, ტექნიკურად შესაძლებელია ფოტოს ეკრანიდან სკანირება ან საჯარო შედეგების მოთხოვნა. ამიტომ თანხა არ გადაირიცხოს ავტომატურად და ყველა განაცხადი გადაამოწმე. თუ მეტი დაცვა დაგჭირდება, დაამატე შეკვეთის დამადასტურებელი უნიკალური ბმული ან OTP.

## 4. მთავარ WestFace მაღაზიასთან დაკავშირება

მთავარ საიტზე შეგიძლია ჩასვა ეს ღილაკი და შეცვალო ახალი AR საიტის მისამართით:

```html
<a href="https://შენი-ახალი-ar-საიტი.netlify.app/" class="mystery-link">
  გახსენი საიდუმლო საჩუქარი 🎁
</a>
```

AR საიტზე მაღაზიაში დაბრუნების ბმული აღარ არის.

## 5. ადგილობრივი ტესტი

```bash
npm install
npm test
npm run build
npx netlify-cli dev
```

ლოკალურად `.env`-ში დააყენე ზემოთ მოცემული ორი ცვლადი და დაამატე ტესტური პოსტერები. ადმინისტრირების cookie უსაფრთხოა და მოითხოვს HTTPS-ს (localhost-ის მხარდაჭერა შეიძლება ბრაუზერის მიხედვით განსხვავდებოდეს), კამერასაც სჭირდება HTTPS ან localhost. ტელეფონით რეალური გამოცდა გააკეთე Netlify-ის HTTPS მისამართზე.

## 6. გამოქვეყნების წინ

- შედეგი წინასწარ, ადმინისტრატორის მიერ არის განსაზღვრული. არ გამოაცხადო შემთხვევითი 5%-იანი მოგების ალბათობა ან შემთხვევითი გათამაშება.
- რეალური ფულადი პრიზების აქციის დაწყებამდე გადაამოწმე საქართველოში მოქმედი წამახალისებელი გათამაშების მოთხოვნები შემოსავლების სამსახურთან. ეს პროგრამა ავტომატურად არ უზრუნველყოფს სამართლებრივ შესაბამისობას.
- საიტზე განათავსე შენი რეალური აქციის პირობები, მოქმედების ვადა, პრიზის მოთხოვნის ვადა, საკონტაქტო ინფორმაცია და კონფიდენციალურობის პოლიტიკა; მხოლოდ საჭირო წინასწარი თანხმობით დაამუშავე პირადი მონაცემები. პრიზების მოთხოვნებს საჯაროდ ნუ გამოაქვეყნებ.
- გახსენი ერთი მოგებული და ერთი არამოგებული ტესტური პოსტერი iPhone Safari-სა და Android Chrome-ში. გადაამოწმე, რომ სწორად ამოიცნობს, ფორმა შენს ადმინისტრირებაში მოდის და ერთი პოსტერის გადახდის სტატუსი მეორედ ვერ ინიშნება. ამოწმებ რეალურ განათებას, ზომასა და ბეჭდვის ხარისხს.

## 7. კოდის დაცვა

- GitHub-ის რეპოზიტორია გადაიყვანე **Private** რეჟიმში (Settings → General → Danger Zone → Change visibility). Netlify-ს დაუტოვე წვდომა. ამით რეპოზიტორიის საწყისი კოდი საჯაროდ აღარ იქნება წაკითხვადი.
- აწყობისას `build.mjs` მომხმარებლის JavaScript-ს ამცირებს (minify) და source map არ ქვეყნდება. მიუხედავად ამისა, ბრაუზერში გაშვებული HTML, CSS, JavaScript და აქტიური AR სამიზნე მონაცემები სრულად დამალული ვერ იქნება.
- მოგების ლოგიკა, ადმინისტრატორის უფლებები, პაროლი, სესიის გასაღები და მოთხოვნები სერვერზეა. არ გადაიტანო საიდუმლოები `public` საქაღალდეში და არ გამოაქვეყნო `netlify/functions` როგორც სტატიკური ფაილები.
- თუ ოდესმე გაგისაჯაროვებია პაროლი ან SESSION_SECRET, შეცვალე ისინი Netlify-ზე. მხოლოდ რეპოზიტორიის დამალვა უკვე გაჟონილ გასაღებს ვერ დაიცავს.

## ბიბლიოთეკები / სტრუქტურა

- `public/index.html` და `app.js` — მომხმარებლის AR ინტერფეისი;
- `public/admin.html` და `admin.js` — ფოტოებისა და მოთხოვნების მართვა;
- `netlify/functions/api.mjs` — სერვერული ლოგიკა და მუდმივი Netlify Blobs საცავი;
- `public/vendor/` — A-Frame 1.5.0 და MindAR 1.2.5, პროექტში ჩასმული ადგილობრივი ფაილები;
- `tests/api.test.mjs` — API-ს ავტომატური ტესტები;
- `licenses/` — მესამე მხარის ბიბლიოთეკების ლიცენზიები.

ოფიციალური დოკუმენტაცია: https://hiukim.github.io/mind-ar-js-doc/ და https://docs.netlify.com/build/data-and-storage/netlify-blobs/ .
